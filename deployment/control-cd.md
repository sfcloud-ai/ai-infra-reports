# 发布器控制程序自动更新

应用 CD 仍负责隔离验证、排空、账本兼容、切换和健康检查。`control_entry.py` 为它提供稳定的 root 信任入口，使 `publisher_cd.py` 及新增配套模块能随主线版本更新，而不是每次手动替换已安装控制程序。

首次安装需要将稳定入口放入 root 所有的 `/usr/local/lib/ai-report-publisher-cd/control_entry.py`，使现有 `publisher-cd.service` 执行该入口的 `tick`。保留现有 timer、账号、配置、镜像、凭据及状态目录；初始 `control-release.json` 和 `code/<commit>/` 必须来自已核实的现役主线。先备份入口、单元和控制记录，验证旧服务健康及回滚，再启用。此代码合入不会自行完成首次安装。

入口独立核实固定报告仓库的 main、前进关系及该 SHA 最新成功的主线 CI。整个 `deployment/` 的普通文件绑定 Git tree、blob 和 SHA256 后进入 root 独占版本目录，拒绝符号链接、超限或不完整来源；Python 文件先通过主机语法检查。任何仓库或 CI 变化都不能借旧成功记录放行。业务控制器只处理入口指定的提交，主线再次前进时先推迟。

切换前持久化控制版本和原应用身份；成功后保留前一控制版本。任务仍在途时，确认原服务与配置未变，再保留原控制版本，下一轮可重试。已确认的执行失败或应用回滚会恢复旧控制版本并阻止同一失败候选；结果未知、配置变化、应用 pending 或健康无法确认时保留意图，只允许核对，不盲目重试。始终不恢复业务数据库、游标或通知 outbox。

这会把受保护 main 中已审查并通过 CI 的部署代码纳入主机 root 信任范围。错误或恶意代码仍可能影响整台主机；来源与哈希校验不是特权隔离。首次扩大该信任范围必须明确批准，不能以普通应用 CD 的名义静默接线。稳定入口本身及账户、凭据、sudo 规则等信任基础不由仓库自动改写。
