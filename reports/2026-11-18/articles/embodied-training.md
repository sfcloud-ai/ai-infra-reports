# 制造业具身智能训练：YAM 采集控制先校验反馈时效

双臂采集时，只重校准左臂，右臂却退出控制循环；读取到电机状态，也不意味着这份状态来自足够新的反馈。这两类问题位于训练数据采集和策略执行之前。LeRobot 的 YAM 改动将每臂正常停止与双臂共享故障分开，并让反馈数值、状态和年龄来自同一帧。

## 实际问题：能读到状态，还要知道它有多新

旧实现由 MotorBridge 读取电机状态，另开一个只接收的 `python-can` socket 判断反馈时间和状态。数值与新鲜度经过两条读取路径，不能直接假定观察到的是同一帧。新实现使用 motorbridge 0.6 的 `get_state_snapshot()`，一次取得状态、状态码及接收帧后经过的时间；年龄由单调时钟计量。

控制器继续要求反馈年龄不超过 `feedback_timeout_s`。异常状态码仍视为故障；电机启用宽限期后仍处于 disabled 状态，也会触发故障。这些判断与返回的电机数值来自同一份最新快照。如果同一电机的一帧故障反馈随后被正常反馈覆盖，控制器读取快照时可能看不到先前的故障码。

## 本次变化：把停止、故障与资源清理分开

| 环节 | 旧路径的问题 | 合并后的行为 |
| --- | --- | --- |
| 单臂重校准 | 双臂共享停止事件，一臂停机会结束另一臂循环 | 每个控制器保留自己的停止信号；共享事件只承载故障 |
| 故障处理 | 普通停止和故障共用事件语义 | 任一臂故障仍停止双臂；故障后拒绝直接重启，需由连接流程清理故障状态 |
| 反馈时效 | 电机数值与接收时间来自两条读取路径 | 从同一快照取得状态、状态码和反馈年龄 |
| 重力补偿 | 计算期间持有控制器锁，阻塞状态读取和目标更新 | 先在锁外计算重力扭矩，再进入受保护的控制更新 |

启动阶段将扭矩启用纳入异常清理：即使只启用了一部分电机后失败，也要尝试关断已启用的扭矩。直接调用控制器的 `stop()` 时，扭矩关断失败会抛出异常。断连时，若控制线程仍活跃，系统会保留 CAN 并向调用方抛出异常，供后续重试。若线程已退出，首次关断失败会记入日志，总线在断连时再次尝试关断；重试成功时调用方可正常返回，仍失败时异常才会传出。这条路径也会清理总线和相机。

这些行为直接作用于采集与执行的可靠性。它们不构成新的训练算法，也没有给出策略成功率、训练吞吐或工厂运行收益。

## 证据范围与复现条件

PR 列出的验证包括单臂及双臂 YAM 硬件，以及 YAM、双臂 YAM、MIT 控制器和 reBot 相关的 **123 项测试通过**。该数字是测试数量，不能换算为数据质量或生产可靠性指标。反馈回归使用显式年龄的模拟快照；它验证判断逻辑，不代表工厂通信条件下的长时实测。

| 条件 | 已有证据与边界 |
| --- | --- |
| 机器人与通信 | YAM 单臂/双臂、CAN 控制流程；不能扩展为所有机器人通用结论 |
| 依赖版本 | `motorbridge>=0.6,<0.7`；开启重力补偿时需要 `placo`，构造阶段即检查依赖 |
| 工作负载 | 启停、反馈新鲜度、单臂重校准及双臂故障联动；没有训练任务或样本规模基准 |
| 比较与指标 | 代码路径和回归断言提供改动前后的行为依据；没有对照训练实验，也没有可用于性能柱状图的吞吐或延迟数据 |
| 工程成熟度 | 改动已合并，证据包括项目测试与 YAM 硬件使用记录；工厂长时运行、完整安全验证和具体发布版本仍需另行确认 |

还有一项会影响复现的输入：重力模型改从 `lerobot/robot-urdfs` 数据集下载 `yam/v1/linear_4310.urdf`，调用没有固定 revision。数据集后续改变可能改变重力补偿扭矩。复现时应固定模型文件版本及其哈希，不能仅固定 Python 提交。

## 对训练链路的价值与下一步

这项更新值得数据采集和策略部署团队检查，因为训练依赖的轨迹首先要经过稳定的控制与反馈链路。最小验证应固定上述代码提交、motorbridge 版本、YAM 配置和 URDF 原件，分别覆盖启动失败、扭矩关断异常、单臂重校准、共享故障以及过期反馈。比较时记录请求的动作、对应反馈年龄、异常与清理结果，再判断是否减少了采集中断或状态不一致；目前不能预先写成质量提升。

单臂停止与共享故障的区分也不是机器人安全认证。硬件现场仍需按设备规范管理支撑、急停与工作空间；代码测试数量不能替代这些条件。
