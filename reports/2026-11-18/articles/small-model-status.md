# 前沿小模型：Qwen3-0.6B 的 GRPO 一步要等多久

在小模型强化学习里，模型参数少，并不意味着训练一步只花在反向传播上。采样要等一批长短不一的回答生成完毕，随后还要算奖励、更新参数，并把新权重交回采样端。Qwen3-0.6B 的一份 TPU v7 配方把这些工作计入同一个步耗时，适合定位训练和推理交替执行时的瓶颈。

原技术文章发布时间为 **11 月 12 日 09:00 UTC**，距本期截止点 133 小时 20 分，属于 168 小时扩窗。案例针对已有 Qwen3-0.6B 的 BF16 GRPO 训练，不涉及新权重发布。训练与采样共用 64 芯片 TPU v7，每步 256 条提示，每条采样 8 次；最终参考配方的提示上限为 4,096 token，回答上限为 8,192 token。配方列出 TP1×DP128，约 29% 的完成序列触达生成上限。换一套长度分布，等待长回答的成本也会改变。

**一次权重更新横跨四个环节。** 采样端持续解码并连续组批，按词表分片执行采样；奖励计算完成后，训练端更新同一模型，最后同步权重。文章的最终软件栈保留已分配的 KV 存储，减少反复申请和释放，但权重更新后仍须使旧前缀失效，并给持有的存储留出足够 HBM。

| 数字来自哪里 | 计量口径 | 如何使用 |
| --- | --- | --- |
| 早期基线 616 秒 | 初始约 6,000 秒和 616 秒均为完整训练步，使用 NuminaMath 与 OpenMath，提示上限为 16,384 token | 从 88 秒阶段起改用 OpenMathInstruct-2 的 train_1M 切分，提示上限为 4,096 token。生成上限仍为 8,192 token，较大的提示上限会预留更多 KV。配方另记含编译首步约 160 秒 |
| 原文最终栈中位数 57.9 秒 | 保留 KV 存储后，20 步中位数由 60.3 秒降至 57.9 秒；最快单步约 56 秒 | 比较同一实验中的内存策略，最快单步另列 |
| 配方参考运行中位数 56.94 秒 | TensorBoard 第 3–20 步，共 18 步；p10/p90 为 55.2/59.3 秒，含生成、奖励、训练、权重同步 | 作为该版本和该负载的复现参照 |

配方 README 固定 MaxText `c28166ca`、Tunix `a3e92fba`、tpu-inference `c2289ee4`、vLLM `51da0ca6`，与文章附录的发布栈及较早测量栈有别。原文指向已合并的 [TPU 配方 #387](https://github.com/AI-Hypercomputer/tpu-recipes/pull/387)，其中列有 JobSet、带依赖版本的镜像构建说明、检查点转换和计时脚本。本期直接核对的是原文及默认分支的 README，未独立取得此次测量实际运行镜像的内容摘要。复现时应一起固定这些版本、样本、奖励函数、长度上限与步数，记录奖励走势和回答长度分布，再讨论等质量成本。仅凭步耗时无法判断训练质量，也无法换算同条件 GPU 的费用。
