# 前沿小模型｜字段抽取的 2B 专用模型，先验质量与可复现性

小模型要按目标任务判断，而不是只看参数量和宣传倍数。本版补查独立文档图像模型，不再只以 GR00T 2 Turbo 代替小模型板块。以下为 11 月 4 日的七日扩窗材料，并非今日新发布。

![专用模型验收链：文档图像与schema输入，JSON输出，再分开检查质量、延迟和成本](assets/small-model-evaluation.png)

## Dharma Field Extractor：面向 schema 的文档字段输出

[Dharma-AI 官方团队文章](https://huggingface.co/blog/Dharma-AI/dharma-field-extractor) 介绍基于 2B DharmaOCR-LITE v1.1 与 LoRA 的字段抽取模型。输入文档图像，按给定 schema 输出带类型的 JSON，也可以自动发现字段。这是针对业务文档的专用路径，不是通用聊天能力的比较。

作者在 546 份文档、1638 个案例的自有评测中报告综合分 0.834，比较对象中最高为 0.816。该指标综合字段路径匹配、Levenshtein 值相似度与有效 JSON 比例，不能改写为通用 OCR 或文档理解准确率。前沿对照配置使用 low reasoning，Claude Opus 5 使用 adaptive 低档，不宜描述成各模型最佳能力下的胜负。

成本按单张 L40S、每小时 2.24 美元的 GPU 时间核算，再与 API 牌价比较。所谓“6–147 倍便宜”对应特定负载和统计口径，不是模型售卖价格，也不是任意硬件、并发、延迟目标下可复现的节省。生产还应计入空闲、排队、重试、人工复核和运维成本，本期未独立复现。

## 发布状态：不能把旧 OCR 权重当作新 2B 模型

本轮没有确认 Field Extractor 2B 本身的公开权重、许可证与完整复现实验。文章链接的旧 OCR 权重不等同于这次模型，旧页面的参数量和许可证也不能替代新版本证据。因此将它作为团队的专用模型研究与部署报告，而不是“新开源 2B 模型已可下载部署”。

适合先用已有带答案的票据、工单或质检文档建立固定集合，分开统计字段漏抽、数值和单位错误、schema 合规、有效 JSON、每页延迟与人工复核率；通过后再测峰值吞吐与成本。没有可部署权重时，不把文章数字直接转为硬件采购结论。

## 与本期其他“小”模型的关系

- [Muse Ember](https://sfcloud-ai.github.io/ai-infra-reports/2026-11-10/model-architecture-status/) 确认的是 API 发布。官方称最小模型，但没有披露参数量或开权重，不能直接认作自托管小模型。
- [GR00T 2 Turbo](https://sfcloud-ai.github.io/ai-infra-reports/2026-11-10/embodied-training/) 是 2B 机器人视频与动作模型；速度更快不代表所有操作任务质量更高，不能外推文档抽取。
- MOSS-Live 的团队文章描述实时多模态交互，但本轮没有确认参数量、开放权重和本地部署条件，因此未把它算作新的可部署小模型。

本轮明确补查了独立文档图像模型及 API 多模态模型，仍不是对所有文本、视觉、小型 MoE 与开权重发布的穷尽搜索。没有证据的参数、许可证、硬件需求和领先幅度均不补写。
