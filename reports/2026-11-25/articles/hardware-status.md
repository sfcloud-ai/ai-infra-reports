# 硬件与算力平台：B200 上的 Gemma 3 如何省掉两张图文注意力掩码

一条 8,192 token 的图文请求进入 Gemma 3 时，滑窗层和全局层原先各生成一张布尔注意力掩码，两张合计 128 MiB。北京时间 11 月 25 日 03:17，TensorRT-LLM 合入 #22463。在符合条件的分页预填充中，同一查询在某一层的可见范围可用左右两个端点表示。滑窗层和全局层分别使用自己的左端点，两者共用右端点。128 MiB 对应这两张掩码，整次推理的显存峰值还取决于同时存活的其他张量。[TensorRT-LLM #22463](https://github.com/NVIDIA/TensorRT-LLM/pull/22463)

## 为什么两个端点就够了

因果或滑窗范围包含当前位置，同一图像内部允许双向观察的区间也包含该位置。两者相交，并集仍是一个连续区间。Triton 内核读取左右端点，跳过范围外的键块。默认分流按批内各上下文长度计算 ΣL²/ΣL，阈值为 8,192。一个长请求配上许多短请求时，要看整个批次的这个值。[分流和内核实现](https://patch-diff.githubusercontent.com/raw/NVIDIA/TensorRT-LLM/pull/22463.diff)

## 强制对照与默认分流

作者在 B200 上用 Gemma-3-12B-it、TP1、BF16 FA2 和单张图片强制运行两条路径，每个长度交替测六对，取中位数。

| 输入长度 | 稠密掩码 | 紧凑掩码 |
| --- | --- | --- |
| 512 token | 59.12 ms | 65.86 ms |
| 7,168 token | 332.39 ms | 203.88 ms |

本组 512 token 测点的稠密路径更快。7,168 这一行说明指定两种路径时的差异，该长度的单请求仍低于默认切换阈值。数据来自变长窗口实现提交 `7f8e57e20a`，作者在合并前最后一次 rebase 后未补测延迟。[分版本实验记录](https://github.com/NVIDIA/TensorRT-LLM/pull/22463)

当前适用范围是符合条件的 FlashInfer FA2/FA3 分页预填充和非 FP8 KV。走 XQA 目标解码的混合批保留稠密掩码。评估线上收益时，可按真实图文长度分布记录实际分流、首轮编译耗时、稳态延迟和峰值显存。在当前 Gemma 3 模型入口，图像上下文要求已有缓存 token 数为零，须禁用分块预填充和 KV 缓存复用。内核层对带前缀输入的测试无法放宽这个入口限制。其他 GPU 尚缺同条件测量。[补丁与覆盖范围](https://github.com/NVIDIA/TensorRT-LLM/pull/22463)
